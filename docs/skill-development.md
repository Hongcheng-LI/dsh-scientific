# Skill 开发指南

## Skill 是什么

Skill 是**给模型的方法论**：一个目录 + `SKILL.md`（frontmatter 写触发条件，正文写工作流程与原则）。模型在任务匹配 description 时调用，按正文步骤执行。与插件工具的分工：**插件管"手"（能调什么），skill 管"脑"（怎么干）**。

## 结构

```
skills/<name>/
└── SKILL.md
```

`<name>` 用 kebab-case。`SKILL.md` 格式：

```markdown
---
name: <name>
description: 一句话说清这个 skill 何时触发（当用户要求……时使用），中英文皆可
---

# 标题

## 流程
1. 第一步（引用具体工具名，如 zotero_fulltext）
2. …

## 原则
- 必须遵守的红线（数值核对、免责说明、需用户确认的节点）
```

## 写好 skill 的要点

1. **description 决定触发率**：写"用户会怎么说"，不要写功能罗列。对比：
   - ❌ "文献综述功能"
   - ✅ "围绕一个研究主题做系统性文献综述……当用户要求'综述/调研某个方向'时使用"
2. **步骤可执行**：每步指明用哪个工具/哪个参数；模糊步骤会让模型自由发挥。
3. **原则部分是护栏**：数值必须回原文核对、免责说明必须给、哪些节点必须问用户——这些写在 skill 里比指望模型自觉可靠。
4. **控制长度**：50~80 行以内；太长模型会跳读。
5. **领域知识是核心价值**：本仓库 skills 的价值在合成生物学/计算化学的方法论本身（如对接打分的经验阈值、MD 平衡判据），不是流程模板——持续用你的专业判断迭代这部分。

## 安装与验证

DSH 从技能目录发现 `SKILL.md`。把 `skills/<name>/` 复制或链接到你的 DSH 技能目录后，在会话里说一句匹配 description 的话，观察 agent 是否按 skill 执行。

## 与 workflow 的区别

`workflows/` 是**人读的操作手册**（多插件端到端组合，含检查点清单）；skills 是**模型读的方法论**。工作流稳定成熟后，可以把其中模型可自主执行的部分沉淀为 skill。
